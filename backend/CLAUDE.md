# Backend

Rules for work under `backend/`. They extend the root CLAUDE.md.

- Read first: `docs/conventions/backend.md`, `docs/conventions/database.md`, `docs/conventions/api.md`, and `docs/domain/glossary.md` for entity, table, enum and route names.
- `docs/domain/data-model.md` is the column-level contract for entities, EF configurations and migrations: names, types, nullability, checks, FKs and enum values. Match it exactly. To change the design, edit `docs/spec-source/data_db.py` and regenerate.
- Identifiers are English. Never use the report's Vietnamese table names (`LichHen`, `NguoiDung`) in code; translate them with the glossary (ADR-0001).
- Business logic lives in `Application/UseCases/<Feature>/` behind `Application/Interfaces/Services/<Feature>/`. Infrastructure holds only EF Core persistence and external adapters (ADR-0002).
- Appointments and work schedules use `DateOnly` + `TimeOnly` in Vietnam local time. Everything else is `DateTime` UTC named `…AtUtc` (ADR-0003). Staff overlap (appointments and active shifts) is guarded by a PostgreSQL `EXCLUDE` constraint as well as an in-transaction check. Which appointments occupy a slot is defined once, in `AppointmentOccupancy`; reuse it. JSON times are `HH:mm` (`HourMinuteTimeOnlyJsonConverter`).
- Map DTOs with hand-written `ToDto()` extensions in `Application/Mapping/`; don't add AutoMapper profiles (ADR-0004).
- Report failures with the domain exceptions the middleware already maps (`BusinessRuleException` 400, `NotFoundException` 404, `ConflictException` 409). Messages are Vietnamese and safe to show users.
- The current user comes from `ICurrentUserService`, never from request bodies. Protect endpoints with `[Authorize]`; for role rules add the permission to `API/Authorization/Permissions.cs` (RBAC table) and use `[Authorize(Policy = Permissions.X)]` (role values are snake_case, constants in `Application/Common/Security/Roles.cs`). Auth failures throw `UnauthorizedException`/`ForbiddenException` with a code, and the middleware returns 401/403 envelopes.
- Integration tests that need a real database use `PostgresFixture` + `AuthApiFactory` (`tests/IntegrationTests/Infrastructure`, collection `postgres`, Testcontainers, Docker required).
- Configurable business values (hold minutes, cancel window, slot step) go in `<Feature>Options`, with defaults from `docs/decisions/open-questions.md`.
- DI: constructor injection into `private readonly _camelCase` fields; do not use primary constructors for injected dependencies (only for pass-through types such as exceptions). See docs/conventions/backend.md.
- Persistence: inject `IRepository<T>` for simple loads and saves. For feature queries, add `I<Entity>Repository : IRepository<T>` in Application and `<Entity>Repository : Repository<T>` in Infrastructure. Commit through `IUnitOfWork`, which turns the overlap `EXCLUDE` violation into `ConflictException("…", "slot_unavailable")`. Enums map to snake_case text by convention, so never add per-property converters.
- After changing an entity or configuration, add a migration. `PersistenceModelTests` fails on pending model changes or drift from `data-model.md`. Raw-SQL objects such as the EXCLUDE constraints live in `AppointmentConstraints` / `WorkScheduleConstraints` and are applied from migrations; map a new constraint name to its error code in `UnitOfWork.Translate`.
- Money and payments: prices are always re-read from the catalog (never from the client); discounts go through `DiscountCalculator` (Domain). The payment gateway is the `IPaymentGateway` port (VNPay adapter in `Infrastructure/Payments`); gateway results are trusted only after `ParseCallback` verifies the signature, and are applied under `IOrderRepository.LockAsync` so duplicates are idempotent. A paid order issues entitlements only through `EntitlementIssuer`.
- Orders (UC-SPA-12/13): cancel only through `OrderCancellation` (order row lock first, then the held appointments), and compute `isPayable`/`canCancel` only with `OrderActionPolicy`, so lists, details and commands agree. The owner never gets the Q-44 block.
- Bookings: an appointment's service is never stored; derive it with `AppointmentServiceSource.WithService` (session → entitlement's order line → own order line, BR-BKG-13). Any write that puts an appointment into a staff member's timetable runs in a transaction, locks the appointment row (`IAppointmentRepository.GetForUpdateAsync`) then the staff row (`IStaffMemberRepository.LockForBookingAsync`, otherwise concurrent EXCLUDE checks deadlock) and, when the time changes, the customer row (`IAppointmentRepository.LockCustomerForBookingAsync`, BR-BKG-04 has no constraint), expires stale holds (`ExpireHeldAsync`), checks overlaps with `AppointmentOccupancy`, and only then saves. Free slots come from the pure `AvailabilitySlots.Compute`. Customer bookings reserve through `BookingSlotReserver.ReserveAsync` (locks every candidate staff row in one `ORDER BY id` statement, then the customer) and create orders only through `OrderPlacement`; read an entitlement for its status untracked first and tracked only after the locks, or EF returns the stale tracked copy. Booking eligibility (`EntitlementEligibility`) and effective purchase status (`PurchaseStatus`) are pure and shared by booking and `/me/purchases`. Customer changes (UC-SPA-16) check `AppointmentChangePolicy` (status, then the 24 h cutoff) and pass `excludeAppointmentId` to `BookingSlotReserver` so the appointment being moved does not block itself; give back what was used to book with `Appointment.ReleaseBookedSource()`.
- Care (UC-SPA-25/27/28): staff scope is checked in the service, not only by policy — the assigned staff member (`appointments.staff_member_id`) for skin profiles and completion, "in care" (`IAppointmentRepository.IsInCareAsync`) for allergies; the owner only reads. Completion locks the appointment (`GetForUpdateAsync`) then the package row (`IPurchaseRepository.GetPackageForUpdateAsync`) and checks the staff member on the locked row. Plan dates use the appointment's date, not today.
- Treatments (UC-SPA-19/20/21): plans outside the caller's scope read as `404 treatment_plan_not_found` (`TreatmentScope`: owner all, primary staff edits, staff with a session appointment view only when `Treatments:AssignedStaffCanView`). Owner-only commands (assign-staff, pause, resume, cancel, complete) check the role in `TreatmentManagementService`, not by policy. Status commands lock the customer row (`LockCustomerForBookingAsync`) then the package row (`GetPackageForUpdateAsync`), so a session booking racing a cancel either commits first or sees the new status. Per-session `canBook` for customers comes from `IPurchaseRepository.GetSessionFactsAsync` + `EntitlementEligibility.ForSession`, never a second copy of the rules.
- Background work runs as hosted services in `Infrastructure/BackgroundJobs` that only call an Application service in a new scope (`OrderExpiryJob` → `IOrderExpiryService`); keep the logic in the service so tests call it directly with `OrderExpiry:Enabled=false`.
- Warnings are errors (`TreatWarningsAsErrors`). Add tests in the matching `tests/` project; see `docs/conventions/testing.md`.
