# Order list and cancellation (UC-SPA-12, UC-SPA-13) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Backend for a customer to list their orders and cancel an unpaid one (with its book-now hold), and for the owner to search, view and cancel unpaid orders.

**Architecture:** Two new columns on `orders` (`cancelled_at_utc`, `cancellation_reason`) with a CHECK, migration `AddOrderCancellation`. A domain `Order.Cancel` + `Appointment.CancelHold`; one shared `OrderCancellation` (lock order row → check → cancel order, expire pending payments, cancel held appointment) used by the customer `OrderService` and a new owner `OrderManagementService`. A pure `OrderActionPolicy` decides `isPayable`/`canCancel` for lists, details and commands. New owner `OrdersController` behind the new `order.manage` policy.

**Tech Stack:** .NET 9, EF Core 9 + Npgsql, PostgreSQL 17, FluentValidation, xUnit + NSubstitute + FluentAssertions, Testcontainers.

**Spec:** `docs/specs/orders.md`, sections "UC-SPA-12 — Quản lý đơn hàng đã mua (đợt 2)", "UC-SPA-13 — Quản lý đơn hàng (đợt 2)", BR-ORD-04, 11, 12, the "Đợt 2" data/API/config tables, ORD-T29…T44, Q-41, Q-43 (reason **required for customer and owner**), Q-44, Q-45. Approved 2026-11-01.

## Global Constraints

- Names from the glossary: folder `Orders` (`UseCases/Orders`, `DTOs/Orders`, `Validators/Orders`, `Interfaces/Services/Orders`); columns `cancelled_at_utc` / `cancellation_reason`, C# `CancelledAtUtc` / `CancellationReason` (same as `appointments`). Routes exactly: `GET /api/v1/me/orders`, `POST /api/v1/me/orders/{id}/cancel`, `GET /api/v1/orders`, `GET /api/v1/orders/{id}`, `POST /api/v1/orders/{id}/cancel`.
- Policies: existing `Permissions.OrderSelf` (customer) for `/me/orders*`; new `Permissions.OrderManage = "order.manage"` → `[SecurityRoles.Owner]` for `/orders*`.
- Error codes. Reused: `validation_error`, `order_not_found` (404), `order_not_payable` (409). New in `OrderErrors`:
  - `order_not_cancellable` (409, `ConflictException`): `"Chỉ hủy được đơn hàng đang chờ thanh toán."`
  - `order_payment_in_progress` (409, `ConflictException`): `$"Bạn vừa mở thanh toán cho đơn hàng này. Vui lòng thử hủy lại sau {minutes} phút hoặc liên hệ spa."` (`minutes` = remaining minutes rounded up, ≥ 1).
- Cancel body for both roles: `CancelOrderRequest(string? Reason)`; validator: not blank → `"Vui lòng nhập lý do hủy."`, trimmed length ≤ 500 → `"Lý do hủy tối đa 500 ký tự."`. Stored trimmed (Q-43: required for everyone, no config).
- Cancellable = `OrderStatus.PendingPayment` only (also after `payment_due_at_utc` while the job has not run). Status is checked after the lock, before Q-44.
- Q-44: `OrderOptions.CancelBlockMinutesAfterPaymentStart` (default `0`, valid `0`–`PaymentTimeoutMinutes`); customer only: blocked while `now < latestPendingPayment.CreatedAtUtc + minutes`. Owner never blocked.
- Hold reason (BR-ORD-12): `$"Hủy đơn hàng {order.Code}: {reason}"`. Only appointments still `Held` change (to `Cancelled`); `HoldExpired` is left alone. Nothing to release (no entitlement yet).
- Lock order: `IOrderRepository.LockAsync(orderId)` first (same lock as `PaymentService.ProcessCallbackAsync` and `OrderExpiryService`), then `IAppointmentRepository.GetHoldsForOrdersAsync`. Someone else's order → `404 order_not_found` right after the lock.
- Lists (BR-ORD-11): date filter on VN date of `created_at_utc` → `[SpaTime.StartOfDayUtc(from), SpaTime.StartOfDayUtc(to + 1 day))`, `fromDate <= toDate`, no range cap. Customer: `CreatedAtUtc desc, Code`. Owner: `sortBy` `createdAtUtc` (default, desc) | `grandTotal`, direction applies only when `sortBy` given (as `PromotionService`), tie-break `Code`; `search` trimmed ≤ 100 chars matches `Code` (contains, case-insensitive) or customer `User.FullName` (accent-insensitive, `AppDbContext.Unaccent`), `User.PhoneNumber`, `User.Email` (contains), with `CatalogSearchText.Contains` + `EscapeCharacter`. Status query value is snake_case; invalid → `400` `"Trạng thái đơn hàng không hợp lệ."`. Paging `PagedQuery` (1/10, max 100).
- A late successful VNPay result for a cancelled order already works (`PaymentService`: payment `succeeded`, order unchanged, warning log). Do not change `PaymentService`.
- Do not change behaviour of finished UCs; `OrderDetailDto` only gains fields (append, with defaults). All existing tests pass; `PersistenceModelTests` passes with the new migration and regenerated `data-model.md`.
- DI through constructors into `private readonly` fields; Application references neither ASP.NET Core nor EF Core. Domain methods throw `InvalidOperationException` on a wrong state, so services check status first and throw the coded errors.
- TDD: unit tests with NSubstitute + fixed clock (`IDateTimeProvider`); integration tests with `PostgresFixture` + `AuthApiFactory` (`Clock`, `Payments`), helpers `OrderApi`, `CustomerBookingApi`.
- The user runs git: no commits or pushes; each "Checkpoint" = build + the task's tests. No Co-Authored-By or "Generated with" lines anywhere.

## Review Focus

- Cancel racing an IPN success on the same order: exactly one wins, no deadlock, no entitlement for a cancelled order → Task 5 test `CancelAndIpnSuccessConcurrently_OneWins` (ORD-T37).
- Order created at 23:59 VN time on day D (16:59 UTC) must appear for `fromDate = toDate = D` and not for D+1; one at 00:00 VN on D+1 the reverse → Task 3 test `DateFilterUsesVietnamDayBoundaries`.
- Owner search for a code typed in lower case or partial (`dh2611`) must match `DH261101…` → Task 4 test `SearchMatchesPartialLowerCaseCode`.
- Cancelling a book-now order whose hold already passed `hold_expires_at_utc` but is still `held` (job not run): must become `cancelled`, the slot free → Task 2 test `CancelsStaleHeldAppointment`.
- Customer cancels an order with a `failed` and a `pending` attempt: only the pending one becomes `expired`; afterwards `isPayable = false` and a new payment attempt is `409 order_not_payable` → Task 5 ORD-T32.
