# Staff & work schedules (UC-SPA-22, 23) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Backend for the owner to manage staff (account + skills + resignation, credentials mailed to the staff member) and to assign, edit and cancel work shifts without overlaps or stranding appointments.

**Architecture:** Application gets `StaffService` and `WorkScheduleService` behind interfaces, plus small helpers (`TemporaryPasswordGenerator`, `StaffAccountEmailTemplates`, `AppointmentOccupancy`). Infrastructure adds `StaffMemberRepository`, `WorkScheduleRepository`, `AppointmentRepository` and an `EXCLUDE` constraint on `work_schedules` (same pattern as `AppointmentConstraints`). API adds `StaffController`, `WorkSchedulesController`, the `staff.manage` / `schedule.manage` policies and an `HH:mm` `TimeOnly` JSON converter. `AuthService` gains one check (BR-STF-05).

**Tech Stack:** .NET 9, EF Core 9 + Npgsql, PostgreSQL 17 (`btree_gist` already enabled), FluentValidation, MailKit via existing `IEmailSender`, xUnit + NSubstitute + FluentAssertions, Testcontainers.

**Spec:** `docs/specs/staff.md` (approved 2026-10-27 with changes: mail the password, future resignation blocks login, 60/42-day limits, deferred items in "Việc để sau")

## Global Constraints

- Code names from the glossary (`StaffMember`, `StaffSkill`, `WorkSchedule`, routes `/staff`, `/work-schedules`); user-facing messages in Vietnamese with diacritics; error codes exactly as the spec (`staff_not_found`, `staff_service_not_found`, `staff_service_discontinued`, `staff_already_resigned`, `resignation_before_hire_date`, `hire_date_after_shift`, `work_schedule_not_found`, `shift_conflict`, `shift_has_appointments`, `shift_date_out_of_range`, `shift_in_past`, `shift_before_hire_date`, `staff_resigned`, `shift_cancelled`; reused `email_exists`, `phone_exists`, `email_send_failed`, `account_inactive`).
- DI through constructors into `private readonly` fields; Application does not reference ASP.NET Core or EF Core.
- "Today" is always `SpaTime.Today(_clock.UtcNow)` (Asia/Ho_Chi_Minh); times are `DateOnly` + `TimeOnly` in VN time (ADR-0003).
- Config: `Staff:TemporaryPasswordLength` = 12 (8–64), `WorkSchedule:MaxDaysAhead` = 60, `WorkSchedule:MaxQueryRangeDays` = 42, in `appsettings.json`, bound with `ValidateDataAnnotations().ValidateOnStart()`. No new `.env` variable.
- The temporary password never appears in an API response, a log line, or the database (only its hash).
- Do not change behaviour of finished UCs (01/02/03/06/07/09) except the BR-STF-05 check; all existing tests pass; `PersistenceModelTests` passes.
- TDD: unit tests with NSubstitute and a fixed clock; integration tests with `PostgresFixture` (Testcontainers) and `AuthApiFactory` (`FakeEmailSender`). Appointments are inserted directly in tests.
- Schema change goes `docs/spec-source/data_db.py` → regenerate `data-model.md`, Excel, `docs/export/NhuNguyetSpa_CSDL_TiengViet.sql` → migration.
- The user runs git: no commits or pushes; every "Commit" step is a checkpoint (`dotnet build` + the task's tests). No Co-Authored-By or "Generated with" lines anywhere.

## Review Focus

- A shift ending at 24:00 cannot be entered (`TimeOnly` max is 23:59): the owner types `22:00–00:00` → expect `400 validation_error` (end ≤ start), not a 500 → Task 5 validator test `EndTimeMidnightIsRejected`.
- Times arriving as `"9:00"`, `"09:00:00"` or `"09:00:30"`: the first two mean 09:00, the last is rejected → Task 7 test `TimeAcceptsHourMinuteAndRejectsSeconds`; responses always `"09:00"`.
- Resignation recorded "today" when it is still yesterday in UTC (17:30 UTC = 00:30 VN next day): must use VN date → Task 3 unit test uses `Now = 2026-10-26T17:30Z`, today = 2026-10-27.
- Email typed with different case or spaces (`" An@Spa.VN "`) when creating staff: stored trimmed, `email_exists` caught case-insensitively → STF-T03 in Task 7 sends the mixed-case form.
- Mail sent but commit fails afterwards (rare): staff receives a password for an account that does not exist; acceptable, but the service must send the mail **after** `SaveChangesAsync` (so unique/constraint errors surface first) and inside the transaction → Task 3 test `CreateSendsMailAfterSaveAndRollsBackOnMailFailure` checks call order with `Received.InOrder`.
