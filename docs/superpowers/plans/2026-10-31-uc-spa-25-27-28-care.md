# Staff appointments (UC-SPA-25) + care: skin profiles, allergies, completion (UC-SPA-27, 28) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Backend for staff to list their assigned appointments, write a skin profile per visit, keep a customer's allergies, and mark a visit completed (entitlement used, or package session completed with package/plan progress).

**Architecture:** Domain gets strict completion transitions (`Appointment`, `ServiceEntitlement`, `TreatmentSession`, `CustomerPackage`, `TreatmentPlan`) and update methods (`SkinProfile`, `CustomerAllergy`). Application gets the new `UseCases/Care` folder (pure `CareRules`, `SkinProfileService`, `CustomerAllergyService`, `AppointmentCompletionService`) and `AssignedAppointmentService` in `UseCases/Staff`. Completion reuses the UC-SPA-17 lock (`IAppointmentRepository.GetForUpdateAsync`) then locks the customer package row. `GET /appointments/{id}` gains additive fields. No schema change, no migration.

**Tech Stack:** .NET 9, EF Core 9 + Npgsql, PostgreSQL 17, FluentValidation, xUnit + NSubstitute + FluentAssertions, Testcontainers.

**Spec:** `docs/specs/care.md` (UC-SPA-27, 28) and `docs/specs/staff.md` § UC-SPA-25 — approved 2026-10-31 with every proposed default (Q-33 hide held, Q-34 7-day window, Q-35 not required, Q-36 staff-in-care writes allergies, PUT + DELETE allergy, BR-CARE-03 as written).

## Review Focus

- Completing the last session when an earlier session is `skipped` (Q-07 on): `used_sessions` must not reach `total_sessions`, package stays `active`, no CHECK violation → Task 1 test `RecordCompletedSessionNeverExceedsTotal` (throws when `UsedSessions == TotalSessions`) and Task 6 test `CompletingWithSkippedSessionKeepsPackageActive`.
- Appointment that started yesterday at 23:30 VN, completed at 00:10 today (UTC day boundary, `TestClock` at `16:40Z`): accepted, plan `start_date` = yesterday's date → Task 2 test `CompleteAcrossMidnightUsesAppointmentDate`.
- Staff reassigned between `GET /appointments/{id}` and `POST complete`: the old staff gets `403 appointment_not_assigned` because the check runs after the row lock on the locked row's `StaffMemberId` → Task 6 test `ReassignedStaffCannotComplete`.
- Allergy duplicate where only accents/case/space differ (`" Parabén "` vs `paraben`), and PUT keeping its own allergen unchanged must not conflict with itself → Task 6 test `DuplicateIgnoresAccentCaseAndSpace`, Task 4 test `UpdateKeepingSameAllergenSucceeds`.
- Skin profile on an appointment whose service came from a book-now order (only `order_item_id` + `service_entitlement_id`) and whose customer has zero allergies: detail still returns `allergies: []`, `skinProfileId` set → Task 6 test `BookNowAppointmentDetailHasSkinProfileId`.
